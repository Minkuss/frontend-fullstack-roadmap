# Персональный интерактивный roadmap для Frontend Engineer

**Дата:** 2026-07-23

**Статус:** дизайн утверждён в диалоге, ожидает проверки письменной версии

**Источник контента:** `/Users/nikita/Documents/my_brain/personal-frontend-skill-map.md`

## 1. Контекст

Исходная карта содержит 22 учебных направления, 117 заголовков и 1958 строк. Она полезна как справочник, но плохо отвечает на ежедневный вопрос «что изучать сейчас». Одновременно видимые темы создают лишний выбор, календарный план превращает паузы в долг, а мелкие пункты не образуют законченных учебных единиц.

Пользователь учится циклом:

1. читает материал;
2. пишет заметку своими словами в Obsidian;
3. создаёт карточки Anki;
4. через несколько дней повторяет материал.

График нестабильный. Поэтому продукт должен измерять завершённые учебные циклы, а не соблюдение недельного расписания.

## 2. Цель

Создать локальный интерактивный web-roadmap, который:

- показывает одну рекомендуемую микротему сейчас;
- сохраняет короткую очередь и полную карту отдельно;
- объединяет мелкие понятия в связные учебные единицы;
- объясняет пользу, зависимости и критерий освоения каждой темы;
- даёт ограниченный набор источников и практику;
- поддерживает цикл Obsidian, Anki и первого повторения;
- позволяет свободно переключаться между маршрутами;
- сохраняет прогресс без backend и аккаунта;
- снижает психологическую нагрузку через progressive disclosure и нейтральный язык.

## 3. Не входит в MVP

- аккаунты, облачная синхронизация и совместный доступ;
- чтение файлов Obsidian или данных Anki;
- автоматическое создание карточек Anki;
- собственная полноценная spaced-repetition система;
- AI-рекомендации и чат;
- уведомления ОС, email или Telegram;
- календарные дедлайны, streak-наказания и соревновательная геймификация;
- редактор учебного контента внутри приложения;
- backend и база данных.

## 4. Принципы продукта

### 4.1. Pull-based обучение

Roadmap не назначает темы по неделям. Пользователь завершает доступный шаг и сам забирает следующий. Пропущенные дни не создают просрочек.

### 4.2. Progressive disclosure

Главный экран показывает:

- один текущий учебный шаг;
- три следующие микротемы;
- ближайшее первое повторение;
- прогресс текущего модуля.

Полная карта доступна на отдельном экране.

### 4.3. WIP-limit

Одновременно активна одна микротема. При ручном переключении прежняя тема получает статус `paused`; её шаги и данные сохраняются.

WIP-limit не запрещает просматривать другие темы и маршруты. Он ограничивает только число активных учебных циклов.

### 4.4. Рекомендации, не запреты

Все маршруты и темы доступны всегда. Зависимости дают предупреждение и объяснение, но не блокируют выбор. Ручной выбор всегда сильнее автоматической рекомендации.

### 4.5. Освоение вместо процента

Прогресс темы выражается этапами учебного цикла. Приложение не утверждает, что пользователь знает направление на абстрактные «47%».

## 5. Информационная архитектура

### 5.1. Экраны

1. **Фокус**
   - текущая микротема и текущий шаг;
   - следующие три темы;
   - первое повторение;
   - прогресс текущего модуля;
   - короткое действие на 10–15 минут внутри текущей темы.

2. **Roadmap**
   - четыре основных маршрута;
   - сквозной pet-проект;
   - фоновые навыки;
   - фильтры по статусу, маршруту и оценке времени;
   - свободный переход к любой теме.

3. **Микротема**
   - ожидаемый результат;
   - оценка суммарного времени;
   - причина изучать тему сейчас;
   - зависимости;
   - основной и запасной источники;
   - инструкции для заметки Obsidian;
   - рекомендации по карточкам Anki;
   - практика;
   - проверка понимания;
   - критерии освоения;
   - управление фокусом и очередью.

4. **Прогресс**
   - освоенные, активная, приостановленные и ожидающие повторения темы;
   - история завершённых циклов;
   - прогресс по модулям и маршрутам без дедлайнов.

5. **Настройки**
   - экспорт прогресса в JSON;
   - импорт с предварительной валидацией;
   - подтверждаемый сброс;
   - базовые настройки отображения.

### 5.2. Иерархия контента

```text
Маршрут
└── Модуль
    └── Микротема
        ├── учебный цикл
        ├── источники
        ├── практика
        ├── зависимости
        └── критерии освоения
```

Термин из исходной карты не обязан становиться отдельной микротемой. Связанные термины объединяются, если их можно освоить одной ментальной моделью и проверить одним набором заданий.

## 6. Группировка исходной карты

Разделы исходного документа о приоритетах, очередности и максимальном карьерном эффекте становятся метаданными рекомендации. Общий критерий освоения превращается в шаблон проверки микротем. Рекомендуемый стек становится основой заданий сквозного pet-проекта.

### Маршрут 1. Модель frontend

Цель: точно объяснять выполнение JavaScript и обновление React UI.

- JavaScript: execution model, значения и ссылки, функции и `this`, прототипы, асинхронность, коллекции;
- React: render/commit, state, Effects, composition, context, устойчивость, формы;
- TypeScript: база типов, narrowing, generics, продвинутые типы, API, React и конфигурация.

### Маршрут 2. Надёжный data flow

Цель: строить безопасную и тестируемую работу приложения с данными.

- HTTP и сеть;
- браузерная платформа;
- TanStack Query;
- frontend-безопасность;
- Vitest, React Testing Library, MSW и Playwright.

### Маршрут 3. Production frontend

Цель: проектировать, измерять и диагностировать production-интерфейсы.

- frontend-архитектура и FSD;
- модули, сборка и code splitting;
- память и производительность JavaScript, React и браузера;
- HTML, CSS и accessibility;
- frontend-observability и production-диагностика.

### Маршрут 4. Fullstack delivery

Цель: доводить вертикальную фичу от UI до базы и deploy.

- Node.js и Fastify;
- SQL и PostgreSQL;
- Docker;
- Caddy и nginx;
- CI/CD;
- backend logging и observability.

### Сквозной pet-проект

Один проект получает практическое расширение после модулей каждого маршрута. Он связывает теорию с рабочим контекстом и постепенно становится портфолио-проектом.

### Фоновые навыки

- Git и командная разработка;
- code review;
- технический английский;
- работа с AI-агентами;
- алгоритмы и структуры данных.

Они не блокируют основные маршруты. Короткие задания могут появляться между основными микротемами.

## 7. Учебный цикл микротемы

| Этап | Действие | Условие завершения |
|---|---|---|
| 1. Источник | Прочитать или посмотреть основной материал | Пользователь отмечает источник изученным |
| 2. Obsidian | Объяснить тему своими словами по подсказкам | Добавлена необязательная ссылка и отмечен шаг |
| 3. Anki | Создать 4–7 карточек на recall и объяснение | Пользователь подтверждает создание карточек |
| 4. Практика | Выполнить короткие задания | Выполнен заданный минимум |
| 5. Проверка | Объяснить модель без конспекта и решить контрольный пример | Пользователь подтверждает критерии |
| 6. Первое повторение | Вернуться к теме через 3 дня | Повторение отмечено; дальше интервалы ведёт Anki |

После этапа 5 тема получает статус `awaiting_review` и `reviewDueAt` через три календарных дня. После этапа 6 тема получает статус `mastered`.

Кнопка «короткий шаг» не переключает направление. Она предлагает ближайшее незавершённое действие текущей темы длительностью 10–15 минут.

## 8. Политика источников

Для микротемы показываются:

- один основной источник;
- один запасной источник только при реальной пользе;
- один источник или среда для практики при необходимости.

Правила отбора:

1. Русский качественный материал используется по умолчанию.
2. Английский источник используется, когда он заметно точнее, актуальнее или является официальной документацией.
3. Приоритет: официальная документация, MDN, спецификации прикладного уровня, признанные учебные ресурсы.
4. Пользователь не получает длинный каталог ссылок.
5. Рядом со ссылкой указываются конкретный раздел, ожидаемое время и назначение.
6. Источники имеют поле `lastVerifiedAt`, чтобы позже проверять актуальность.

## 9. Алгоритм рекомендации

Автоматическая рекомендация детерминирована и объяснима.

1. Если есть активная тема, вернуть её.
2. Если пользователь вручную выбрал тему, сделать её активной; прежнюю активную тему приостановить.
3. Если активной темы нет, проверить ручную очередь и выбрать первую доступную тему.
4. Если очередь пуста, выбрать тему по приоритету маршрута, порядку модуля и выполненным зависимостям.
5. Если строгих кандидатов нет, предложить ближайшую тему с предупреждением о недостающих зависимостях.

Наступившее первое повторение показывается рядом с фокусом, но не заменяет текущую тему автоматически.

Причина рекомендации выводится в UI: например, «продолжить начатое», «первый пункт очереди» или «база для React Effects».

## 10. Состояния

Статус микротемы:

- `not_started`;
- `active`;
- `paused`;
- `awaiting_review`;
- `mastered`.

Для каждого этапа хранится отметка завершения и время изменения. Дополнительно хранятся:

- ссылка на Obsidian;
- ручная очередь;
- дата первого повторения;
- история освоения;
- версия схемы пользовательских данных.

Просмотр темы не меняет её статус.

## 11. Техническая архитектура MVP

- React, TypeScript и Vite;
- статический клиент без backend;
- структурированный контент хранится в репозитории;
- стабильные идентификаторы маршрутов, модулей и микротем;
- схема контента и импортируемого прогресса валидируется во время сборки и выполнения;
- пользовательское состояние хранится в `localStorage`;
- JSON-экспорт содержит версию схемы и дату создания;
- миграции сохраняют прогресс при изменении структуры контента.

Поток данных:

```text
Встроенный roadmap + локальный прогресс
                |
                v
      recommendation engine
                |
                v
       Focus / Roadmap / Topic
                |
                v
       события учебного цикла
                |
                v
      versioned local storage
```

Recommendation engine остаётся чистой функцией без доступа к браузеру. Хранилище, контент и UI общаются через типизированные интерфейсы.

## 12. Ошибки и восстановление

- Импорт сначала валидируется; повреждённый файл не заменяет текущий прогресс.
- Перед успешным импортом текущие данные предлагается экспортировать.
- Сброс требует явного подтверждения и описывает удаляемые данные.
- Неизвестные идентификаторы из старого прогресса сохраняются в отчёте миграции, а не молча теряются.
- Отсутствующая тема или источник показывает понятное состояние и путь назад.
- Ошибка `localStorage` не ломает просмотр карты; UI сообщает, что прогресс не сохранён.
- Внешние ссылки открываются отдельно. Наличие запасного источника смягчает link rot.

## 13. Визуальный дизайн

Выбран вариант **«Тихий кабинет»**.

- тёплый светлый фон;
- тёмный оливково-графитовый текст;
- терракотовый акцент только для основного действия;
- редакционная типографика для заголовков и нейтральный sans-serif для интерфейса;
- мало рамок и декоративных карточек;
- спокойные плоские поверхности вместо типичного SaaS-dashboard;
- нормальный регистр текста, короткие инструкции;
- отсутствие красных просрочек, streak-давления, конфетти и наказаний;
- анимация только функциональная, с поддержкой `prefers-reduced-motion`.

Интерфейс должен быть адаптивным, доступным с клавиатуры, иметь заметный focus state и достаточный контраст.

## 14. Тестирование

### Unit

- выбор активной темы;
- приоритет ручной очереди;
- рекомендация по зависимостям;
- ручное переключение и статус `paused`;
- расчёт `reviewDueAt`;
- миграции версий;
- валидация контента и импортируемого JSON.

### Component

- переходы шести этапов;
- добавление и удаление Obsidian-ссылки;
- отображение зависимостей;
- состояния без активной темы, без очереди и с наступившим повторением;
- недоступность сохранения при ошибке хранилища.

### End-to-end

- начать тему, перезагрузить страницу и продолжить с того же шага;
- переключиться на другой маршрут и вернуться к приостановленной теме;
- завершить этап 5, увидеть повторение, завершить этап 6;
- экспортировать, сбросить и восстановить прогресс;
- отклонить повреждённый импорт без потери текущих данных;
- пройти основной сценарий клавиатурой на desktop и mobile viewport.

## 15. Критерии готовности MVP

1. Все направления исходной карты представлены в четырёх маршрутах, сквозном проекте или фоновых навыках.
2. Мелкие пункты объединены в последовательные микротемы с устойчивыми идентификаторами.
3. Каждая микротема имеет цель, время, источник, практику, зависимости и критерий освоения.
4. Пользователь может начать, приостановить, продолжить и освоить тему.
5. Можно свободно выбрать любую тему независимо от маршрута.
6. Главный экран всегда объясняет текущий и следующий шаг.
7. Первое повторение появляется через три дня и не дублирует дальнейшую работу Anki.
8. Прогресс переживает перезагрузку, экспорт и импорт.
9. Ошибка данных не приводит к молчаливой потере прогресса.
10. Интерфейс соответствует направлению «Тихий кабинет» и не создаёт календарного долга.

## 16. Возможные расширения после MVP

- настройка пути к Obsidian vault и создание шаблона заметки;
- экспорт предложенных вопросов в формат Anki;
- облачная синхронизация;
- несколько профилей обучения;
- встроенная проверка ссылок;
- диагностический self-assessment;
- адаптация очереди по результатам практики;
- push-напоминание о первом повторении.
